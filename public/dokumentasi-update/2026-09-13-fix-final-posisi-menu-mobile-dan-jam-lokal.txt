2. AKAR MASALAH NAVIGASI MOBILE
----------------------------------------------------------------

Navigasi mobile memakai:
    position: fixed; bottom: 0;

Tetapi komponen tersebut dirender sebagai anak dari Header.
Header menggunakan:
    backdrop-filter / backdrop-blur

Pada Chrome Android, parent yang memakai backdrop-filter dapat membuat
elemen fixed di dalamnya tidak lagi mengacu ke viewport layar. Elemen
fixed menjadi seolah-olah mengacu pada kotak Header.

Akibatnya:
    bottom: 0

dihitung sebagai bagian bawah HEADER, bukan bagian bawah LAYAR.
Itulah alasan menu Beranda/Kerjaan/Baru/Shift/Pelanggan muncul di atas
seperti terlihat pada screenshot.


3. SOLUSI ROBUST: REACT PORTAL
----------------------------------------------------------------

Navigasi mobile sekarang dirender menggunakan React Portal:

    createPortal(mobileNavigation, document.body)

Artinya navigasi dipindahkan langsung ke document.body dan tidak lagi
menjadi anak Header.

Manfaat:
- backdrop-filter Header tidak dapat memengaruhi posisi nav.
- position fixed kembali mengacu ke viewport.
- bottom: 0 benar-benar berarti bagian bawah layar.
- Perilaku konsisten pada Chrome Android, PWA/TWA, dan desktop emulation.

Teknik ini sama dengan solusi popup foto yang sebelumnya mengalami
masalah fixed/transform.


4. CSS POSISI EKSPLISIT
----------------------------------------------------------------

Class baru:
    .mobile-bottom-nav

Dikunci dengan:
    position: fixed !important;
    inset: auto 0 0 0 !important;
    top: auto !important;
    bottom: 0 !important;
    width: 100% !important;
    z-index: 70 !important;
    transform: translateZ(0);

Penggunaan !important di sini disengaja untuk mengalahkan style cache
atau utility CSS yang mungkin konflik pada browser/PWA lama.

8. MASALAH TANGGAL/JAM
----------------------------------------------------------------

Sebelumnya Dashboard memakai:

    formatDateTimeID(new Date())

di Server Component.

`new Date()` dijalankan di server Vercel, bukan di HP pengguna.
Server bisa menggunakan zona waktu UTC atau region berbeda.
Karena itu tanggal dan jam bisa berbeda dari perangkat.


9. SOLUSI JAM LOKAL LIVE
----------------------------------------------------------------

Komponen baru:
    src/components/LocalDateTime.tsx

Jam sekarang:
- Dihitung di browser/perangkat pengguna.
- Mengikuti zona waktu sistem HP/laptop.
- Update setiap 1 detik.
- Refresh saat tab/aplikasi kembali terlihat.
- Menampilkan zona waktu singkat jika browser menyediakannya.

Contoh:
    13 SEP 2026, 12.52.36 WIB

Bukan lagi waktu server Vercel.

Jika jam tetap salah setelah update, periksa pengaturan Android:
    Settings -> Date & Time
    aktifkan "Set time automatically"
    aktifkan "Set time zone automatically"

Print Flow akan mengikuti jam yang dilaporkan perangkat/browser.

11. LANGKAH SETELAH DEPLOY (PENTING)
----------------------------------------------------------------

1. Push semua file ke GitHub.
2. Tunggu Vercel Ready.
3. Di Android:
   - Tutup semua tab Print Flow.
   - Tutup PWA dari Recent Apps.
   - Tunggu 5-10 detik.
   - Buka kembali.
4. Login kembali bila diminta.

Jika masih menampilkan menu di atas:
1. Buka Print Flow di Chrome.
2. Tekan icon setting/site info di address bar.
3. Site settings -> Storage / Clear & reset.
4. Tutup Chrome, buka lagi.
5. Login ulang.

Jika memakai PWA terpasang:
1. Hapus PWA/shortcut lama.
2. Clear site data Chrome untuk domain tersebut.
3. Buka URL Vercel lagi.
4. Install ulang.

Data pekerjaan TIDAK hilang karena tersimpan di Neon.
Yang terhapus hanya cache/session perangkat, sehingga perlu login ulang.
